# 计划李个人博客：获奖级品质实施方案

日期：2026-10-02
状态：方案待确认，尚未执行网站改造
范围：全站设计、内容呈现、交互、静态生成与质量验收
规划深度：Deep；范围策略：shape，在现有网站上深化，保留品牌识别。

## 1. 目标与完成定义

按以下要求执行后续建设：

> 以 Awwwards、Webby Awards、FWA 获奖级网站为品质标准，完成后从排版、留白、视觉层级、色彩、动效、微交互、响应式和原创性上自检并持续优化，直到没有明显可提升之处。

“获奖级”是设计和工程的质量目标，不代表已经获奖，也不保证评奖结果。下面的数值门槛是本项目内部验收标准，不冒充任何奖项的官方评分。

“没有明显可提升之处”指在约定页面、设备、浏览器和状态范围内，所有能够明确指出位置、影响及改进方向的问题均已解决。它不等于网站永远无法改进，也不允许用“主观审美”掩盖可复现的缺陷。

## 2. 依据、现状与边界

### 2.1 奖项参考方法

- Webby 当前公开的网站评审维度包含内容、结构与导航、视觉设计、功能、交互、创新及整体体验。本方案据此要求全站体验完整，不能只交付一张好看的首页。[官方评审标准](https://www.webbyawards.com/judging-criteria/)
- Awwwards 作为视觉完成度和交互细节的对照来源；FWA 作为原创数字体验的对照来源。这是项目选用的参考方向，不是对两者官方评分规则的转述。本轮 Awwwards 评审页访问超时，FWA About 页面未返回可读正文，不引用未经核实的权重。
- 实施第一阶段从三个奖项的官方作品库各选一个相关案例，记录作品名称、官方获奖/入选页面、年份、适用页面及不适合借鉴之处。优先个人网站、出版阅读和文化档案类，不以重型品牌宣传站作为性能基线。
- 每个案例最多提炼两项原则，例如中文阅读密度、导航反馈、图文节奏；不复制版式、素材或标志性动画。参考作品信息不完整时不宣称它获过奖。

### 2.3 保留与不做

本轮不做：重写为 SPA、引入后端服务、引入新的统计账户、全站 WebGL/3D、光标劫持、滚动劫持、背景音乐、为展示效果制造个人经历、批量改写文章正文、未经确认的发布和推送。

旧版偏好的包豪斯方向是设计起点；本次提高质量允许重新组织层级和组件，但不默认授权更换为另一种品牌风格。

## 3. 路线选择

| 路线 | 工作量 | 主要收益 | 主要不足与风险 | 复用基础 |
| --- | --- | --- | --- | --- |
| A：只修故障、轻调样式 | 小 | 快速恢复可靠性；改动容易回退 | 多套样式和模板继续分裂；原创性提升有限 | 现有 award.css/js |
| C：重做沉浸式实验网站 | 大 | 视觉表达空间大；可做独特叙事 | 容易压过阅读；移动性能与维护成本高 | 少量内容和品牌资产 |

推荐 B。先以首页、归档页、长文章作为样板，再迁移专题。避免在未确认的设计上同时改完全站；也避免修完表面问题后留下难以维护的内容结构。

## 4. 设计主张：一本持续更新的生活实验档案

读者包括首次从分享链接进入的访客，以及回来寻找某篇文章的人。核心任务依次是：知道作者写什么，找到值得读的内容，读完，继续探索。

视觉记忆点选为“橙色坐标标记”：用网格交点、栏目编号和细小的橙色定位符，把首页主题、文章目录和专题索引联系起来。它服务于定位和内容组织，不做漂浮装饰，也不把编号伪装成实验数量或读者统计。

### 4.1 排版与留白

- 保留 Noto Sans SC 作为中文标题与界面字体，Noto Serif SC 用于长文；JetBrains Mono 仅用于日期、编号、代码。先优化现有字体，不增加字体家族。
- 标题靠字重、尺寸和结构建立层级；不依赖全大写英文标签证明设计感。主标题按语义断行，小屏允许自然换行，不使用固定宽度遮掉中文。
- 起始字号：桌面首页主标题 64–88px，手机 36–48px；页面标题 32–48px；正文手机 17–18px、桌面 18–20px；重要辅助文字至少 14px。数值以真实长标题验证后收敛。
- 文章行高 1.75–1.9，桌面正文约 32–38 个汉字一行；窄屏自然缩减。正文不铺满整张宽屏。
- 桌面外层内容宽度上限约 1200px；手机两侧留白 20px，320px 窄屏可降至 16px；专题与文章正文独立控制宽度。
- 使用 4/8/12/16/24/32/48/64/96 的间距序列。桌面章节间距 72–112px，手机 40–64px，依据内容分组选择，不平均铺满所有区块。
- 同类元素对齐同一网格；栏目间留白显著大于卡片内留白。卡片只用于可独立进入的内容，不为每段文字套框。

### 4.2 色彩与材质

- 基底延续 #f4f4f0、文字 #0a0a0a、品牌强调 #FF4D00。蓝与绿只用于稳定的栏目或状态语义。
- 长文正文区域保持低干扰；网格只在外围、首页和栏目开场保留，避免透过正文持续抢注意力。
- 橙色优先用于定位、下划线、边缘和少量色块。小号橙字或白字橙底必须单独测量对比度，不因为是品牌色而豁免。
- 正文与辅助文字对比度至少 4.5:1；大字及关键非文字控件至少 3:1。这是项目采用的可访问性门槛，实际逐对颜色检查。
- 边框 1–2px、常态阴影 0–4px；只有少量重点模块使用 6–8px。避免每个卡片都像主按钮。

### 4.3 动效与微交互

| 场景 | 设计 | 边界 |
| --- | --- | --- |
| 首屏 | 标题、说明、行动入口依次完成轻微入场，整体约 400ms | 无遮罩，无等待进度；JS 失败照常显示 |
| 章节定位 | 橙色标记随当前章节变化 | 不劫持滚动，不改变阅读位置 |
| 文章链接 | 下划线或边框增强；悬停位移最多 2px | 键盘聚焦提供等价反馈；点击区域不移动失控 |
| 按钮 | 按下时硬阴影收缩，80–140ms | 不缩小触控范围，不依赖磁吸行为 |
| 菜单 | 180–240ms 显隐，焦点进入与返回明确 | Esc 可关闭；背景不可误触；调整尺寸后恢复滚动 |
| 搜索与分类 | 结果、计数、空状态一致更新 | 不用动画推迟结果；重置同时清空全部筛选状态 |
| 减少动态效果 | 移除入场位移、平滑滚动和装饰动画 | 内容和操作能力完整保留 |

移除普遍应用的卡片 3D 倾斜和磁吸按钮。动效保留的依据是帮助辨认位置、层级或状态，不以动画数量验收。

## 5. 页面实施设计

### 首页 index.html

顺序：导航 → 一句话说明作者与内容 → 主行动“阅读文章”与次行动“关于作者” → 一篇重点文章和两到三篇近期内容 → 主题入口 → 简短作者介绍 → 页脚。

首页重点文章采用不对称网格，主文面积明显大于次文，手机按阅读顺序单列排列。首屏不放访客计数器；在 390×844 的真实 CSS 视口中，主行动完整可见，并尽量让下一内容区露出入口。若长标题导致拥挤，先调整标题与间距，不缩小正文。

### 文章归档 blog.html

保留分类与搜索，以阅读查找效率为主。桌面采用较克制的两栏文章列表，手机单列；每条包含标题、短摘要、分类、日期和阅读时间。分类数量从实际数据计算。

搜索覆盖标题、摘要、标签；分类与搜索同时生效。保留或恢复现有标签筛选能力，不静默删除。URL 中的分类与有效搜索状态可分享，浏览器前进/后退恢复对应视图。空状态提供一个真正重置所有条件的按钮。

### 文章详情与生成模板

统一文章标题、元信息、正文、引用、列表、代码、图片说明及前后文链接。宽屏目录位于正文旁；空间不足时收进可展开目录。锚点考虑导航高度，不把标题遮住；目录激活不得触发自动回滚或抢焦点。

### 关于 about.html

以真实经历为骨架：简短自述 → 关键时间节点 → 当前关注 → 可验证的作品/证书 → 联系方式。恢复自然的第一人称表达，删除无法核实的服务数量和自创模型名称。只有事实依据明确时才展示数字。

### 咖啡 coffee.html

保留器具、豆子、探店、冲煮日记四类内容，统一 tab 的选中状态、键盘行为和展开控件。无 JS 时各区块仍可阅读，使用锚点到达。照片和风味/冲煮信息成为主要内容，避免四层嵌套卡片。

### 看世界 travel.html 与回忆录 gallery.html

使用真实地点、日期和照片构成档案节奏。看世界强调地点与游记入口；回忆录强调影像与简短说明。保留原链接和筛选能力；没有真实素材的区域采用诚实空状态。图片预留尺寸、按显示尺寸加载，首屏以下懒加载，禁止用虚构照片冒充经历。

### 认知武器 visual-design.html

强调条目索引、标题和概念关系，减少纯装饰封面。已有独立作品保持各自表达，只统一外层导航、返回路径和可访问性；不为了全站一致重写作品内容。

## 6. 工程方案与数据边界

公共样式收敛为一个入口：styles/main.css 管理设计变量、基础排版及公共组件；styles/article.css 与现有专题样式只负责局部。award.css 与 neo-brutalism.css 按引用清单逐步退出，迁移完成前不直接删除。禁止再叠加第四套全局覆盖样式。

公共脚本由 scripts/main.js 承担导航和通用交互；搜索及专题行为分别维护，模块须兼容没有对应 DOM 的页面。迁移 award.js 的有效逻辑并修复状态问题，清除重复监听。保留原生 JS，不新增动画框架。

| 改动位置 | 责任 | 验证重点 |
| --- | --- | --- |
| update_blog_html、update_index_html | 注入动态区域 | 使用明确区域边界；替换数量必须等于预期，否则失败退出 |
| 新增或提取的 templates/ 源文件 | 公共导航和生成页面结构 | 消除手工页面与生成页面的双份规则 |
| generate_search_index.py、generate_sitemap.py | 衍生产物 | 内容真实、URL 不变、无开发页面混入 |

## 8. 八维自检与迭代机制

每项按 1–5 分记录：1 为阻断使用，2 为明显缺陷，3 为基本可用但仍有明显改进，4 为已精修且没有明确未解决问题，5 为在真实内容与多场景下表现出鲜明、成熟的完成度。全部至少 4 分；均分不能抵消单项不合格。

| 维度 | 必查问题 | 证据 |
| --- | --- | --- |
| 排版 | 中文断行是否自然；长标题是否挤压；正文、元信息与代码是否易区分 | 真实最长标题、长文和字体失败后的截图 |
| 留白 | 内容分组是否清楚；是否有无意义空洞；手机是否连续多屏看不到内容 | 各页完整截图与章节连接处裁图 |
| 视觉层级 | 第一眼能否识别页面目的；一个区域是否存在多个争抢注意力的重点 | 首页首屏、列表、正文的灰度与缩略图检查 |
| 色彩 | 颜色是否有稳定语义；强调色是否过量；文字与控件对比是否达标 | 色彩角色表、实测对比度、各状态截图 |
| 动效 | 是否表达关系；是否拖延阅读；快速操作是否打断动画状态 | 正常与减少动态效果模式的操作记录 |
| 微交互 | hover、focus、active、空结果、清除、关闭、错误是否完整 | 键盘与触屏路径、结果计数及状态检查 |
| 响应式 | 内容是否重排而非缩小；是否截断或溢出；横屏与放大后是否可用 | 测试矩阵、实际 CSS 视口值、溢出检查 |
| 原创性 | 去掉名字后是否仍有作者内容特征；布局是否由内容决定；是否只是奖项站套路 | 三项原创决定及对应内容证据、参考差异说明 |

每轮流程：查看真实页面 → 记录问题与截图 → 按影响排序 → 只改有证据的问题 → 重测受影响页面与流程 → 更新八维评分。问题记录包含页面、尺寸、复现步骤、读者影响、修改方式和验证结果。

问题优先级：P0 为数据损坏或无法访问；P1 为主要路径失败或事实错误；P2 为可访问性、明显视觉/响应式/交互缺陷；P3 为局部精度问题。所有 P0–P2 必须清零；P3 若仍可明确指出收益，也应修复。仅限纯偏好冲突可写明取舍，不能靠降级优先级绕过验收。

两轮完整自检均无新增明显问题，且全部八维达标，才达到本轮收敛条件。若仍能提出具体改善，应继续迭代；若受工具、素材或访问权限阻挡，明确标为未完成，不以轮次上限宣布完成。

## 9. 功能、设备与性能验收

### 9.1 测试矩阵

- CSS 视口：320、390、768、1024、1440、1920px；首屏另测 390×844、1440×900；测试手机横屏、200% 缩放及 320px 重排。
- 记录实际 innerWidth 和截图尺寸，不能把模拟器设定尺寸当作有效证据。上轮移动预览曾出现设定宽度与实际视口不一致，须重新验证。
- 浏览器：当前稳定版 Chromium、Safari/WebKit、Firefox；手机至少一次真实 Safari 或 Chrome 检查。环境缺失时记录未测，不标全平台通过。
- 页面：七个一级页面全部检查；文章样本覆盖最长标题、最长正文、图片较多、代码/表格、最短内容；全量页面执行链接和结构检查。

### 9.2 必须通过的操作

1. 从首页进入归档，组合搜索与分类，打开文章，返回后保持合理状态。
2. 搜索无结果后重置：输入、分类、标签、计数和列表一起恢复。
3. 手机打开菜单后所有链接可触达、可被读屏读取；Esc 关闭并还原焦点；桌面/手机切换不残留滚动锁。
4. 文章目录跳转正确、不遮挡标题、不自动回跳；代码和表格局部横向滚动不推动整页。
5. 咖啡标签页与展开内容可用键盘操作；没有 hover 的设备仍可获得完整信息。
6. 同一份内容生成两次结果稳定；模板更新后卡片、导航和搜索仍一致；已发布 URL 无变更。

### 9.3 项目性能预算

- 在固定版本工具、固定移动设备模拟和网络条件下，每个代表页面测试三次，保存中位数和最差值。
- Lighthouse 移动端性能目标至少 90，可访问性至少 95；分数用于发现问题，不替代手工验收。
- 关键页面实验室目标：LCP ≤ 2.5s、CLS ≤ 0.1、TBT ≤ 200ms。INP ≤ 200ms 是上线后有足够真实访问样本时的跟踪目标，不能用 Lighthouse 分数替代实测 INP。
- 新的公共 CSS+JS gzip 合计预算 ≤ 100KB；首页初始传输预算 ≤ 1MB，包含实际首屏字体与图片。超预算先缩减装饰、字体字重和图片，不牺牲正文。
- 不加载运行时 Tailwind CDN 生成器作为最终公共样式策略；现有专题使用的工具类在迁移前逐项覆盖，不能直接移除导致失样式。
- 首屏之外图片懒加载；所有图片预留比例；字体使用合理回退，避免闪烁与大幅位移；禁止用隐藏内容换取更高性能分。
